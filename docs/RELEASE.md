# Release and publication acceptance

## Truthful scope

The capability catalog is complete intended scope. A release declares exactly what is
implemented, integrated, verified and accepted. An attractive synthetic demo, a collection
of endpoints, or successful native generation is not full product replacement.
Later printing preparation remains committed later scope, clearly distinguished from the
baseline rather than silently forgotten. Reprioritization/removal requires owner approval.

## Pre-1.0 and v1.0.0

Development has no supported production installations. Test clean recreation and current
same-version restore; do not maintain compatibility with every experimental schema.
Before v1.0.0 cut, establish the supported data/API/package/workflow baseline and future
migration policy. A version string alone does not make the product accepted or authorize
resetting an installation.

## Qualification

Run the planned integration/release checks for exact code, tool and image versions. Include
human and authorized agent journeys, native-tool reality, concurrency/permissions,
interrupted work, missing/unknown conditions, independent engineering expectations,
portable subassembly packages, original source retrieval, and rights closure.

Reconcile supported predecessor workflows and migrations by explicit disposition. Preserve
unknowns/lost semantics rather than fabricate matches. Test fresh ownership/startup without
external dependencies, safe stop/restart, tool enablement, current backup/restore into empty
state, resource behavior, and declared platform/tool compatibility.

Physical qualification is separate. Release records can acknowledge unresolved physical
checks but cannot turn a clean DRC or mesh into a measured assembly result.

## Publication boundary

Review outgoing source/history/authorship, binary/package metadata, screenshots, catalogs,
fixtures, logs and source maps. Run secret detection plus private identifying-string checks
outside public CI. Do not publish tracker content or private source inventories. Human
review remains needed for business-sensitive designs that contain no obvious secret token.

Retain third-party notices, compatible licenses and exact corresponding source as required.
Check entire export/release closure, not only visible top-level files. Unknown asset rights
can block a public package even when a private preview was permitted.

## Release evidence record

Record revision, images/tools, acceptance IDs, commands/results, environments, known gaps,
acknowledged unresolved checks, privacy/rights review and restore evidence. Keep private
operator details in private records; publish only the generalized release notes and evidence
appropriate for distribution. Failed or deferred checks are never silently renamed passed.
