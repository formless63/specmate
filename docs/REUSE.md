# Reuse policy

Prefer direct reuse or adaptation of a working domain implementation over rewriting it to
match the new application's language. A fresh application foundation is not a reason to
lose existing cable visualization, preparation, documents or native-tool knowledge.

The public repository contains no private inventory of source repositories. Maintainers
can supply read-only sources privately. Record public provenance only for material actually
approved for distribution. Do not copy personal comments, private fixtures or business
catalogs into public history to inspect them later.

## Review unit

Compare modules, algorithms, fixtures and workflows, not whole stacks. For each candidate,
record exact source revision/path, dependency boundary, rights evidence, behavior/tests,
embedded assumptions, adaptations and disposition. Useful dispositions are reuse, adapt,
reference-only, replace-with-reason, or blocked-pending-access/rights. Do not presume that
an older/newer repository is a complete superset without comparison.

Preserve readable upstream source and notices where required. Add adapters around good
interfaces rather than a broad rewrite. Reuse TypeScript renderers in React and, if needed,
an on-demand Node document pack; keep Python authoritative records/calculation services.
Do not duplicate authoritative engineering rules in two languages indefinitely.

## High-value candidates

Look for shared cross-section layouts, conductor callouts, layered tube/centerline geometry,
coax shield handling, preparation calculations, React Flow projections, lazily loaded 3D,
document helpers, electrical passage interpretation, native CAD recipes, tool adapters and
known failure/recovery handling. Existing images are regression clues, not proof of accuracy.

Geometry views and preparation rules need special separation. A hidden foil layer, a
particular retained braid percentage or one-end drain landing can reflect a specific
workshop process. Move those into explicit profiles instead of universal defaults. Actual
construction and electrical bonds must survive display simplification.

## Port completion

The port has mapped occurrence/source IDs, clear input ownership, public-safe fixtures,
retained rights and relevant regression checks. It works through the new command/job/view
boundary. A renamed package that still writes the old database or bypasses authorization
is not a completed port. A mock reproduction is not evidence of an imported tool adapter.

Do not require a new document engine to replace an existing capable exporter. WireViz is
an optional adapter, not the canonical cable schema. Typst fills documented needs rather
than mandating reimplementation of every existing PDF.
