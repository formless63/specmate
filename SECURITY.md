# Security reporting

Do not put credentials, private designs, logs containing personal data, or exploit details
into a public issue. Once repository hosting is configured, maintainers must enable and
verify a private vulnerability reporting channel and document it here before release.
**No reporting address or response SLA is claimed by this bootstrap.**

For the threat model, authorization rules, execution isolation, and publication controls,
read [docs/SECURITY.md](docs/SECURITY.md). The absence of supported production users before
v1.0.0 does not relax confidentiality or host-execution controls.
