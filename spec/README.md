# Requirement catalog

`capabilities.json` indexes complete scope with stable IDs and baseline/later horizons.
`acceptance.json` defines observable obligations and integration journeys. They contain
no implementation status. The selected work tracker owns task state, and actual test
records identify verification for exact commits/tools/inputs.

These JSON files are software-development specifications, not a file-based engineering
catalog for end users. Use targeted schema/contract changes and preserve IDs for traceability.
Acceptance entries are scenario specifications, not a claim that runnable tests exist.
Add implementation tests and result references as each capability becomes real.
