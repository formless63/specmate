# Board and firmware workflow

Preserve uploaded originals and discover supported intake/authoring tools and formats.
Review extraction coverage, components/pads/nets/outlines/holes, population and candidate
ports/models. Expose schematic/PCB disagreements; never invent lost semantics. A purchased
black-box board can retain declared interfaces without a complete schematic.

Use authorized native editing/build stages against exact source snapshots. Inspect actual
ERC/DRC and output reports, retain tool/source provenance, and distinguish optional routing
from a guarantee of a qualified layout. Do not install/execute arbitrary imported code on
the host to evade an unavailable tool capability.

Resolve firmware by board occurrence, population, pins and exact target/toolchain. Compilation
produces an artifact and possible flashing handoff, not permission to flash or proof of
operation. Hardware and firmware changes expose affected assumptions/evidence. Report
unresolved fit, electrical and commissioning checks explicitly.
